**One migration**, `20260925090000_department_head_and_unique_name`. It runs by itself when the API
container starts — the image's start command is `prisma migrate deploy` followed by the server. You
do not run it by hand.

It is safe against live data: it de-duplicates department names *before* creating the unique index,
so it cannot fail on rows already in your table, and it backfills each department's head to whoever
the old regex would have chosen, so nothing is lost.

## The commands

```bash
ssh -p 2222 root@217.76.59.244
cd /opt/pdash

# 1. Take the code, rebuild, restart. The migration runs on boot.
git pull origin main
docker compose up -d --build

# 2. Wait for the API to be healthy before running anything against it.
docker compose logs -f api | grep -m1 "listening on"      # Ctrl-C once it prints

# 3. Permissions, roster, reporting lines — IN THIS ORDER.
#    The role has to exist before anybody can be put on it, and people have to be on
#    their roles before the lines are drawn from them.
docker compose exec api node packages/db/prisma/dist/regrant-roles.js
docker compose exec api node packages/db/prisma/dist/roster-align-2026-08.js
docker compose exec api node packages/db/prisma/dist/reporting-lines-2026-08.js

# 4. Optional — fills the policy library, which is currently empty.
docker compose exec api node packages/db/prisma/dist/seed-policies-2026-08.js
```

## What each step should print

If a step prints something else, stop and read it rather than carrying on.

**`regrant-roles`**
```

Business Development 1 role(s) × 42 perms
Role permissions re-synced from catalog ✓
```
The 42 is the check: Employee's 40 codes plus `deal.view` and `deal.manage`. If Business
Development shows **0 perms**, the script did not run — that is the state the local demo copy is in.

**`roster-align-2026-08`**

```

**`reporting-lines-2026-08`**
Expect a full 26-line chart. The four that matter, because they are the ones you reported wrong:
```
Ankit Verma        -> Mohit Kalra      (you stated this)
Anant Gupta        -> Yash Bhargava    (you stated this)
Ajay Sharma        -> Nitin Goel       (was reporting to the VP)
Rajesh Joshi       -> an SRA           (was reporting to the VP)

Contabo currently holds the **old** lines, derived from who manages a project, so expect a lot of

```

```
Re-running it later updates rather than duplicates — but it matches on title, so if HR has since
rewritten a policy and kept its title, a re-run would overwrite their version. Run it once.

## If something goes wrong

```bash
# What the API is actually doing
docker compose logs --tail 100 api

# Did the migration apply?
docker compose exec db psql -U pdash -d pdash -c \
  "select name from _prisma_migrations order by finished_at desc limit 3;"

# Roll the code back — data is unaffected, the migration is additive
git reset --hard HEAD~1 && docker compose up -d --build
```

Nothing here deletes data. The migration only adds a column and an index, and every script is
written to be run more than once.
