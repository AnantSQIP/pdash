Part 1Clients and patents

Agreed 12 August. The theme was identity: giving a client a code, tying patents to work, and being able to say what a relationship amounts to.

Typed client codes with a suggested default. Archive and Remove as genuinely different actions — archive is reversible and destroys nothing, Remove is a real delete and is refused while any patent or project still points at the client. Patents can be tagged to a project after creation, not only while creating it. The client ledger arrived as its own screen, with figures recomputed on every read rather than stored, plus a Super-Admin override that records who stated what and when. formerHandles means a patent ID quoted from an old email still resolves after a client-code rename.

Part 2Team spaces and the BD pipeline

Agreed 13 August. The theme widened to work that is not client delivery.

Every piece of work in the system was a client project — enforced, not conventional. HR and BD work had nowhere to live but a "General" project sitting in the delivery list. Team spaces became their own destination with their own boards and members, deliberately kept off the delivery spine: no PID, no client, absent from both ledgers and from delivery reports.

BD got a full pipeline rather than a lead list: deals with values and stages, activity history, forecasting, and win/loss reporting. Losing a deal requires a reason, because the aggregate answer to "why do we lose" is the most useful thing the pipeline can produce.

Internal work now counts in all three measurement modules. Timesheet.teamId keeps three states apart that were previously one ambiguous blank: project set means client work, team set means internal, both empty means genuinely awaiting a PID.

Part 4The latest batch — PR #100

Built and tested on 23 August. Not yet merged, so not yet on the live system.

01Self as project manager

"May run a project" and "may mint the PID" had been folded into one flag — and only Admin and Super Admin can mint. So every Manager and Senior Consultant was told to hand their own matter to an Admin purely because they cannot issue a number. The two are now separate.

02Feedback

An observation about a colleague, recorded while it is still accurate. Anyone may write one; the author, HR and the subject's reporting manager may read it — the subject cannot, as you specified. The composer says so plainly, because feedback a person cannot see is feedback they cannot answer.

03Client ledger

A client was a code and a name, so nothing knew a rate and money could never be derived. It now carries contact, country, industry, account manager and a rate — so value is computed as hours × rate and moves with the work. The — in the PID column now says whether a PID is pending or was never requested.

04Patent ID ↔ number mapping

Three tiers, with project membership as the grant. A member sees the real numbers for their own matters — in both directions — without seeing which client they belong to. Every reveal is audited by count, never by number.

Row 11360° project feedbackNow unblocked

The question that blocked this — can the person see their own rating — you have since answered for the feedback module, and the same answer applies here.

NeedsNothing from you. This is a build, and it is ready to start.

Billable hours are done. Nobody has said what "Input" measures — pages produced? searches run? claims charted? I could invent a definition, but a productivity metric the firm does not recognise is worse than none, because people will be measured by it.
